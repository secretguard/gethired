## Research notes

### Practical assessment format (P1, 2026-08-01)
Researcher subagent studied TryHackMe, HackTheBox, LetsDefend, and CyberDefenders' beginner-friendly, no-infrastructure content before the assessment was designed. Key findings that directly shaped the build:
- The pattern that makes checkpoint-based assessment work without human grading: a small, self-contained static artifact (a log excerpt, a connection summary, a code snippet — never a live target) + one narrow question with one correct short-string answer. Everything reduces to a fact extractable from the artifact (an IP, a value, a category name) — exactly what rule-based string-match validation can grade.
- **Multi-step, single-scenario challenges beat isolated single-flag questions**: CyberDefenders/HackTheBox Sherlocks reuse one artifact for 2-4 sequential questions that mirror an investigation's natural order (what happened → who → when → what next), which is both more realistic and cheaper to author than TryHackMe's many-tiny-flags-per-task pattern. Adopted this as the core scenario shape.
- No partial credit within a question (pass/fail exact-match, consistent across all four platforms); answer normalization (lowercase/trim/whitespace-collapse) plus a small accepted-synonym list per answer is the standard way these platforms avoid false negatives on reasonable phrasing (e.g. "sql injection" vs "sqli"). Adopted both.
- No hints in v1 (hint systems need extra authoring/scoring-penalty logic TryHackMe uses but the others mostly skip) — deferred, not built.
- Concrete example challenges the agent brought back per category (SSH brute-force log pivot, SYN-scan connection pattern, vulnerable SQL string concatenation, IDOR bug report, impossible-travel SOC alert, etc.) directly informed the 10 scenarios actually written into `data/assessment-scenarios.json` (original wording, not copied from any platform).

## Research notes (v4)

### Find Your Path questionnaire design (V4-P0, 2026-08-01)
Researcher subagent studied real precedent before writing any question, rather than inventing generic personality-quiz content:
- **The universal axis is offensive vs. defensive**, framed almost identically across sources: CompTIA's own career-path guidance poses it as "are the challenges of breaking into systems appealing (offensive), or does the satisfaction of thwarting attacks and securing networks provide motivation (defensive)?"; LetsDefend's SOC-vs-pentester comparison sharpens it to "SOC analysts ask 'what happened?', pentesters ask 'how could we get in?'" — directly informed Q1 and Q6.
- **A third axis (infrastructure/build) comes from the NICE Workforce Framework** (NIST SP 800-181r1): Securely Provision, Protect and Defend, and Analyze map cleanly onto Network Security Engineer, SOC, and VAPT respectively — used to ground the "daily task" and "problem-solving mindset" questions.
- **Work-rhythm differences are well documented**: SOC is shift-based/24-7/alert-driven, pentesting is engagement-based with a deliverable report, network security engineering is steady long-term infrastructure ownership — became Q3 directly.
- **Scoring precedent** (ScoreApp's documented "highest-scoring category" quiz pattern): fixed small integer point values per option, sum per category, highest wins, with an explicit tie-break rule rather than leaving it undefined. Adopted a >=2-point-margin tie-break falling back to Generalist (a real track, not an arbitrary default) rather than guessing between two closely-matched tracks.
- **Question count**: Coursera's comparable cybersecurity career quiz uses 10 questions at 5-10 minutes; landed on 7 as the sweet spot for this project's "quick" framing — enough that one outlier answer doesn't flip the result, short enough to avoid drop-off.
- Full sourcing (comptia.org, letsdefend.io, niccs.cisa.gov, coursera.org, sans.org, onetcenter.org, support.scoreapp.com) preserved in this session's transcript; the resulting 7 questions and point values are in `data/find-your-path-questions.json`.

### Role-specific skill emphasis for the four tracks (V3-P0, 2026-08-01)
Researcher subagent studied real SOC/VAPT/Network-Security-Engineer entry-level job posting patterns (Glassdoor/Indeed/Naukri), the NICE Workforce Framework's Cyber Defense Analyst / Vulnerability Assessment / Network Services work roles, and cert bodies' own positioning (CompTIA's Security+ -> CySA+ vs. Network+ -> CCNA progressions, eJPT vs. OSCP framing) before any corpus weight was assigned. - **PowerShell is genuinely dual-purpose but skews SOC, not VAPT** — cited for Windows AD exploitation in VAPT sources, but surfaces far more consistently in L1/L2 SOC/DFIR skill lists (Windows incident investigation/automation) than in generic VAPT tool lists where Metasploit/Burp dominate.
